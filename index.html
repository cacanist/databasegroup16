Introduction

Introduction

This project transforms a massive, unmanageable CSV dataset into a secure and efficient SQL-based relational database.

By centralizing web sessions and purchase records, we eliminate data anomalies and ensure real-time accuracy to power reliable business analytics.

Objectives

  • Streamline Analytics: Build a secure database to easily track user journeys from first visit to final checkout.
  • Ensure Data Quality: Create a scalable, 3NF-compliant relational model to cleanly manage complex customer and transaction data.

Objectives

Client's Ask

Understand the customer

Who is buying, by country, age group, language, device?

Audit site performance

Are certain devices or browsers hurting conversion?

Evaluate timing & marketing

Which months, weekends, and traffic sources actually pay off?

Drive strategy

Give management evidence-based answers, not guesses.

Our Goal

Model the data properly

Eliminate redundancy and anomalies by normalizing to 3NF.

Explicit entities, keys, and relationships are fully documented.

Deliver a query library

SQL that answers each client question on the new schema.

Tell the story

Turn raw tables into a business narrative the client can act on.

What We Deliver

12 tables with proper keys and FKs to eliminate update anomalies and redundant rows.

Reusable SQL Library

5 business-facing queries covering time, visitor, device, country, and buyer profile.

Key findings: peak month, most profitable channel, device UX issues, and under-served segments.

Bottom line: the client moves from a single unmaintainable CSV to a documented, query-ready database that tells them who buys, when, and how they arrived, so marketing and product budgets can be reallocated with evidence.

Why UNF is a Problem

Anomalies

Insert

Can't store a new visitor without also creating a session for them.

Update

Renaming a country requires updating thousands of rows and risks inconsistency.

Delete

Deleting the last session from a country also erases the country itself.

Redundancy & Dependencies

Non-atomic values

Multiple values crammed into one cell (e.g., Campaign = "BlackFriday, Welcome").

Repeating groups

Three sub-groups per session: Administrative / Informational / ProductRelated (count + duration).

Transitive dependencies

Month → Quarter, Browser_ID → BrowserVersion, Country → Region.

Visitor duplication

Country, Age_Group, AccountCreated repeated on every session row.

1NF: Atomic Values, No Repeating Groups

  • Every cell holds one atomic value
  • Repeating groups → separate PAGE_ACTIVITY table
  • Every row uniquely identified by a key
-- SESSION_1NF: repeating groups removed
CREATE TABLE SESSION_1NF (
    Session_Id  INT PRIMARY KEY,
    VisitorType VARCHAR(50), Country VARCHAR(50),
    Language    VARCHAR(50), DeviceType VARCHAR(50),
    Browser_ID  INT, Month   VARCHAR(20),
    Quarter     INT,  Revenue TINYINT, ...
);

-- PAGE_ACTIVITY_1NF: unpivoted from UNF
CREATE TABLE PAGE_ACTIVITY_1NF (
    Session_Id    INT NOT NULL,
    Page_Category VARCHAR(50) NOT NULL, -- 'Administrative'|'Informational'|'ProductRelated'
    Page_Count    INT, Duration DOUBLE,
    PRIMARY KEY (Session_Id, Page_Category),
    FOREIGN KEY (Session_Id) REFERENCES SESSION_1NF(Session_Id)
);

INSERT INTO PAGE_ACTIVITY_1NF
SELECT Session_Id, 'Administrative', Administrative, Administrative_Duration FROM UNF

SELECT Session_Id, 'ProductRelated', ProductRelated, ProductRelated_Duration FROM UNF;

2NF: Remove Partial Dependencies

  • Every non-key attribute must depend on the whole key
  • Visitor attributes → new VISITOR table
  • SESSION uses FK references instead of copying data
-- VISITOR_2NF: visitor attributes extracted
CREATE TABLE VISITOR_2NF (
    Visitor_ID     INT AUTO_INCREMENT PRIMARY KEY,
    VisitorType    VARCHAR(50), Country VARCHAR(100),
    Age_Group      VARCHAR(20), Language VARCHAR(30),
    AccountCreated DATE, LastSeen DATETIME
);

-- SYSTEM_CONFIG_2NF: device/browser extracted
CREATE TABLE SYSTEM_CONFIG_2NF (
    Config_ID INT PRIMARY KEY, OperatingSystems INT,
    Browser INT, BrowserVersion VARCHAR(30),
    DeviceType VARCHAR(20), ScreenResolution VARCHAR(20),
    JavaEnabled BOOLEAN
);

-- TIME_CONTEXT_2NF: temporal data extracted
CREATE TABLE TIME_CONTEXT_2NF (
    Time_ID INT PRIMARY KEY, Month VARCHAR(20),
    SpecialDay DOUBLE, Weekend BOOLEAN,
    HourOfDay INT, Quarter INT, IsHoliday BOOLEAN
);

-- SESSION_2NF: FKs replace copied columns
CREATE TABLE SESSION_2NF (
    Session_ID INT PRIMARY KEY,
    Visitor_ID INT, Config_ID INT, Time_ID INT,
    TrafficType INT, Revenue BOOLEAN,
    SessionDuration DOUBLE,
    FOREIGN KEY (Visitor_ID) REFERENCES VISITOR_2NF,
    FOREIGN KEY (Config_ID)  REFERENCES SYSTEM_CONFIG_2NF,
    FOREIGN KEY (Time_ID)    REFERENCES TIME_CONTEXT_2NF
);

Normalization: Step 3

3NF: Transitive Dependencies

  • No non-key attribute depends on another non-key attribute
  • Month → Quarter, Browser → Version, Country → Region 
-- 3NF: Extract transitive dependencies

-- MONTH_INFO: Month → Quarter
CREATE TABLE MONTH_INFO (
    Month VARCHAR(20) PRIMARY KEY, Quarter INT
);

-- BROWSER_INFO: Browser_ID → BrowserVersion
CREATE TABLE BROWSER_INFO (
    Browser_ID INT PRIMARY KEY, BrowserVersion VARCHAR(30)
);

-- COUNTRY_REGION: Country → Region_ID
CREATE TABLE COUNTRY_REGION (
    Country VARCHAR(100) PRIMARY KEY, Region_ID INT
);

-- VISITOR: Region removed, Country → FK
CREATE TABLE VISITOR (
    Visitor_ID INT PRIMARY KEY, VisitorType VARCHAR(50),
    Country VARCHAR(100), Age_Group VARCHAR(20),
    Language VARCHAR(30), AccountCreated DATE,
    FOREIGN KEY (Country) REFERENCES COUNTRY_REGION
);

-- SYSTEM_CONFIG: BrowserVersion removed, Browser_ID → FK
CREATE TABLE SYSTEM_CONFIG (
    Config_ID INT PRIMARY KEY, OperatingSystems INT,
    Browser_ID INT, DeviceType VARCHAR(20),
    ScreenResolution VARCHAR(20), JavaEnabled BOOLEAN,
    FOREIGN KEY (Browser_ID) REFERENCES BROWSER_INFO
);

-- TIME_CONTEXT: Quarter removed, Month → FK
CREATE TABLE TIME_CONTEXT (
    Time_ID INT PRIMARY KEY, Month VARCHAR(20),
    SpecialDay DOUBLE, Weekend BOOLEAN, HourOfDay INT,
    IsHoliday BOOLEAN, FOREIGN KEY (Month) REFERENCES MONTH_INFO
);

-- SESSION: final 3NF fact table
CREATE TABLE SESSION (
    Session_ID INT PRIMARY KEY, Visitor_ID INT,
    Config_ID INT, Time_ID INT, TrafficType INT,
    Revenue BOOLEAN, SessionDuration DOUBLE,
    FOREIGN KEY (Visitor_ID) REFERENCES VISITOR,
    FOREIGN KEY (Config_ID)  REFERENCES SYSTEM_CONFIG,
    FOREIGN KEY (Time_ID)    REFERENCES TIME_CONTEXT
);

Capabilities: What Does This Architecture Actually Do?

We will walk you through five specific UI capabilities mapped directly to your expanded scope requests.

  1. Visitor Browser Matrix (Analytics & Reporting)
  2. Unique Monthly Visitors (Seasonality)
  3. Relational Region Updates (Operations)
  4. Page Visit & Suggestion Attribution (Expanded Scope)
  5. Surgical User Deletion (GDPR & Compliance)

Q1: Visitor Browser Matrix

SELECT
    v.Visitor_ID, v.VisitorType, cr.Region_ID, v.Country,
    bi.Browser_ID AS Browser, bi.BrowserVersion
FROM VISITOR v
JOIN  COUNTRY_REGION    cr ON  v.Country     = cr.Country
LEFT JOIN SESSION       s  ON  v.Visitor_ID  = s.Visitor_ID
LEFT JOIN SYSTEM_CONFIG sc ON  s.Config_ID   = sc.Config_ID
LEFT JOIN BROWSER_INFO  bi ON  sc.Browser_ID = bi.Browser_ID
ORDER BY v.Visitor_ID;

Q2: Unique Monthly Visitors

SELECT
    tc.Month,
    mi.Quarter,
    COUNT(DISTINCT s.Visitor_ID) AS Visitor_Count
FROM TIME_CONTEXT tc
JOIN MONTH_INFO mi ON  tc.Month   = mi.Month
JOIN SESSION    s  ON  tc.Time_ID = s.Time_ID
GROUP BY tc.Month, mi.Quarter
ORDER BY Visitor_Count DESC;

Q5: Surgical User Deletion

UPDATE SESSION SET SuggestedBy = NULL WHERE SuggestedBy = 1;
DELETE FROM PAGE_VISIT WHERE Session_ID IN (SELECT Session_ID FROM SESSION WHERE Visitor_ID = 1);
-- ... (cascades through metrics, activity, sessions, suggestions) ...
DELETE FROM VISITOR WHERE Visitor_ID = 1;
7 step bottom up deletion order
1
 Nullify SuggestedBy references in SESSION
2
 Delete PAGE_VISIT records
3
 Delete PAGE_METRICS records
4
 Delete ACTIVITY_LOG records
5
 Delete SESSION records
6
 Delete SUGGESTION records
7
 Delete VISITOR profile
Referential integrity remains 100% intact. No orphaned records. No accidental page deletions.
A 7 step bottom up deletion protocol safely unwires user footprints without violating strict foreign key constraints.
